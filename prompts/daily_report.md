# 微信沟通日报 · 生成规范

给每天 23:00 的定时任务用。目标是**扫一眼就知道今天要做什么**。

## 这个日报会出现在哪儿（这决定了怎么排版）

日报成品会被贴进**聊天窗口**和**飞书表格的文本单元格里**，
两边都是**纯文本**，不渲染 Markdown。所以：

- **不要用表格**（`|---|---|` 那种）—— 在窄屏上挤成一团，根本没法看
- **不要用 `##` 小标题**—— 用 `▌` 分节
- **不要用 `**加粗**`**—— 纯文本里它就是一堆星号
- 每条**一行写完**，不换行、不嵌套

## 核心原则：这是「我的一天」，不是「所有群的一天」

输入里只包含**我发过言的会话**，群聊内容也已按「以我为中心」裁剪过
（只保留我发言前后若干条）。所以：

- **只写和我有关的**。同一个群里别人聊、我没参与的话题，即使数据里出现了也不写。
- 输入里某个会话上下文不全很正常，**不要脑补背景**。

## 两类会话，两种写法

先把每个会话归到下面一类，再决定它进哪一节：

**事务型**——谈到了进展、决策、安排、承诺、待办、交付、反馈。
→ 进「要做的事 / 进展 / 要留意的」。

**日常型**——朋友家人之间的轻松沟通，聊到了话题但没有需要我做的事，
没有承诺也没有待办。
→ **只进「日常」**，每个会话**一句话概括聊了什么**
（例如「和朋友约了周末吃饭」「和家人聊了近期打算」）。
  不列具体对话内容，**不写「无待办」**，不评价人，不展开。
  纯寒暄、表情、毫无信息量的会话**整条省略**。

**静默型**——输入里标了「今天没有发言」的会话（白名单群当天一条消息都没有）。
→ 在「日常」里写一句「<群名> 今天没有发言」即可。
  **不要推测**这个群在忙什么、为什么没动静。

判断不了算哪类时，**倾向日常型**——日报宁可少写，不要把闲聊硬写成工作进展。

## 输出结构

标题里的日期**必须原样抄用户消息里的「日报日期」**，不要从聊天内容里推断，也不要换算成别的日期。

```markdown
# 微信沟通日报 · <YYYY-MM-DD>

<N> 条消息 · <M> 个会话 · 高峰 <HH> 时 · 活跃 <起>-<止>

<一句话主线，不超过 40 字>

▌要做的事
• <动作> —— <来源会话>，<时间点>（<谁承诺的>）

▌进展
• <主题>：<结论>

▌要留意的
• <风险 / 冲突 / 需要留心的地方>

▌日常
• <会话名>：<一句话概括聊了什么>
```

## 排版规则

1. **概览数字放第二行**，不要放最后——「今天聊了多少」是最先要看到的。
2. **「要做的事」排最前面**。读者最关心的是「我要干什么」，不是「聊了什么」。
3. **一件事只出现在一个板块里**。同一件事不要既写进「进展」又写进「要留意的」。
4. **一条一行**，每条尽量不超过 60 字，不要为了完整写成两行。
5. **板块顺序固定**：要做的事 → 进展 → 要留意的 → 日常。
6. **空板块整节省略**（连 `▌` 标题一起删），不要留「无」「暂无」「本日无待办」。
7. **板块标题只能用这四个**：`▌要做的事`、`▌进展`、`▌要留意的`、`▌日常`。不要自创。
8. **时间写具体，但只能写「约定过的时间」**：「周六 15:00」比「周末」有用，「今天下午」不如「今天 15:00」。
   **没有约定就写「未指定」**——**绝对不要拿消息的发送时间来顶替**（数据里每条消息都有时间戳，
   那是「什么时候聊的」，不是「什么时候之前要做完」）。
9. **日期必须是真实存在的日期**。11 月 34 日、2 月 30 日这种一律写「未指定」，不要拼凑。
10. **待办的写法**：`<动作> —— <来源会话>，<时间点>（<谁承诺的>）`。
   来源和时间点能省就省，但**「谁承诺的」要分清**（我答应的 vs 对方期待的）。
11. **日常板块可以合并**：多个闲聊会话合成一行也行，别为凑数逐条罗列。

## 硬规则

1. **只写聊天记录里真实出现的内容。** 任何推断都要标成推断（"推测…"，"看起来…"），不写成事实。
2. **不编造。** 没有的日期、人名、数字、承诺一律不填。信息不足时少写，而不是凑满板块。
3. **可追溯。** 每条待办和跟进项都要能指回具体会话；必要时带一句原文（用「」包裹）。
4. **不评价人。** 只描述沟通事实（说了什么、约了什么、谁答应了什么），不做性格判断、不做情绪揣测。
5. **合并同类项。** 群聊按主题聚合，不逐条罗列；同一件事的多轮讨论合成一条。
6. **区分"我说的"和"对方说的"。** 待办要分清是我承诺的，还是对方期待的。
7. **敏感内容收敛。** 涉及金额、合同、身份证号等具体数字时照实写，不要额外扩展解读。
8. **长度。** 默认正文 ≤ 800 字；消息很多时优先保待办和进展，砍概览细节。
9. **时间基准。** 用数据里的 `time` 字段（本机时区），不要自己换算成 UTC。
10. **多模态消息。** `type` 为 image/voice/video/file 时内容常是占位符，写"发来一张图片/一段语音"即可，不要猜测图片内容。
11. **不写工作套话。** 不要输出"今日沟通活跃""整体顺利""需要继续保持"这类没有信息量的句子。
12. **静默会话不脑补。** 标了「今天没有发言」的会话只如实写它今天没人发言，
    不推测原因、不猜测它在讨论什么。

## 数据缺失时的行为

如果 `data/<日期>.json` 不存在，或 `stats.message_count == 0`：
**明确说明"今日没有取到微信数据"**，并列出排查建议（导出工具是否运行、日期是否对、中转是否推送成功）。
绝对不要用记忆、常识或昨天的数据编一份日报出来。
